# EPG 控制台 2.12

Docker / 极空间频道与节目管理后台，镜像为 `zsz520/epg-console:2.12`（Linux amd64）。

## Docker Hub 直接部署

镜像 `zsz520/epg-console:2.12`，也提供 `latest`。使用本仓库 compose.yaml，保留现有 data 映射和 IPv6 NAT。镜像架构为 Linux amd64。

```sh
docker compose pull
docker compose up -d
```

新部署默认 admin/admin，升级不重置账号。

## 升级部署（默认一个容器）

1. 备份原 data，停止旧 web、crawler，导入 epg-console-2.12-linux-amd64.tar.gz。
2. 在原项目使用新版单容器 compose.yaml，保留原项目名称、data 绝对路径或相对路径、8000:8000 和 IPv6 网络。移除旧 crawler、init-data 容器，不删除 data。命令行可在原项目目录执行 docker compose up -d --remove-orphans。
3. 只运行一个 web 服务：command: ["all"]。同一容器完成目录权限初始化、迁移及网页/调度启动。初始化后自动降为 UID/GID 10001，网页与任务均以该用户运行。
4. 原账号、数据、设置和 data/sources 均沿用。此前配置的 IPv6 NAT 定时服务保持不变，不需要新建诊断容器。
5. 强制刷新浏览器。确认一个容器正常运行，后台显示工作进程在线。

如继续使用分容器模式，使用 compose-multi.yaml；其中 web 明确 command: ["web"]，crawler 使用 scheduler。不要同时运行单容器模式和旧 crawler。

## 新部署

导入镜像，在 Compose 文件所在目录运行 docker compose up -d；或直接在极空间导入 Compose 项目。端口、账号与目录映射集中在 compose.yaml，自动抓取参数在设置中心设置，数据保存在映射的本地 data 目录。

- 公开首页：http://NAS地址:端口/
- 后台：http://NAS地址:端口/admin/
- 新部署默认账号和密码均为 admin，可通过环境变量 DJANGO_SUPERUSER_USERNAME / DJANGO_SUPERUSER_PASSWORD 覆盖。首次密码同时写入 data/admin-password.txt；升级不重置已有账号。
- XMLTV：/download/all.xml；压缩包：/download/all.xml.gz。
- DIYP：/api/diyp/?ch=频道名&date=YYYYMMDD；节目网页：/api/web/?ch=频道名。

前台顶部仅保留后台管理，XML/Gzip 下载集中到同一面板，接口说明默认折叠，节目页移除重复的频道列表入口；分类导航、搜索和后台频道顺序沿用。修正设置中心和维护中心的重复标题。

## 2.11.1：每日首次全量重抓开关

设置中心 → 抓取与历史 → “每天首次抓取时重抓全部节目”，默认关闭。

开启后，当天下一次整批抓取会刷新所有启用频道在“抓取未来天数”范围内的已有节目。例：抓取天数为 2，则今天和明天一起重抓。仅此轮独立覆盖总重抓开关及频道当天重抓开关；停用频道或无节目表频道仍不参与，来源顺序/备用开关/重试次数照常执行。

轮次结束后将日期保存在数据库，当天后续任务恢复原有逻辑，重启和更新不会重置。各频道的请求失败按原逻辑保留旧数据，该轮正常结束仍记为已执行；进程中断或导出异常未能完成轮次则不记录完成，后续整批任务可以重试。单独抓取选中频道、来源目录任务和网页预览不占用首次机会。

设置页面显示最近完成日期。运行日期在任务开始抓取时固定，跨午夜的长任务不会在循环中跳过日期。新增迁移 0019 仅添加最近完成日期字段，不改已有频道和节目。

## 2.10.1：当天重抓修复、总开关与界面更新

快捷编辑 / 补全弹窗已加入频道重抓选项，包含并发修改校验；旧版提交遗漏该字段时保留原值。XMLTV 已有节目重新入库同样遵循两个开关，文件下载更新流程继续独立执行；若希望当天重新读取已有 XMLTV 节目，也请开启相应频道重抓。

频道列表的分类输入框和来源下拉框统一为 160×40 像素。后台、首页、节目页和快捷编辑页面新增右下角“回到顶部”，滚动后出现，支持键盘及减少动画偏好。

## 2.9.1：三轮逻辑、功能与界面修复

- 抓取遍历：被拒绝的频道放到队尾再尝试一次，不再卡在原频道，其他频道照常处理。
- 缺失补抓：按所请求日期是否存在原始节目判断，不再仅依赖“最新节目日期”，避免未来日期较新却漏抓中间缺失日。
- 来源重试：主来源和每个备用来源统一遵循“单来源最大尝试次数”（包含首次）；设置中心新增失败重试等待，默认 1 秒，可设 0–30 秒。有效备用来源可以接替失效或缺少映射的主来源；关闭备用开关时不换源。成功后不改频道保存的主来源。
- 返回校验：错误频道、错误日期、来源标记失败但附有部分记录、空标题、同一开始时间的冲突节目均不再作为成功；完全重复的节目合并。失败保留旧快照。
- 预览与网页：仅有其他日期节目不再误报当天成功；真实节目与“精彩继续”补全分开计数、标注。没有节目的网页使用空状态。DIYP 尊重补全开关，并优先精确匹配自定义 tvg-id，保留大小写。
- 定时：修改未使用的定时参数不会重置当前计划；兼容 2.9 保存的调度状态。取消排队的间隔任务后，等待完整间隔再执行；取消和调度更新放在同一事务中。
- 任务界面：间隔任务排队/运行时不再显示虚假的下次时间；只读用户不显示取消按钮，完成任务隐藏按钮；日志大小提示采用实际设置。登录失效时轮询提示重新登录。
- 预览缓存增加来源文件版本信息，避免更换脚本后仍显示旧预览。

本版无需新数据库迁移；升级保留原 data、端口和现有来源脚本。完整排查与验证见“修复记录-2.9.1.md”。

## 2.9：节目单与频道列表独立定时

在后台左侧“设置中心”分别配置“节目单自动抓取”和“频道列表自动抓取”，每组都有独立开关和定时方式：

- 每隔一段时间：填写数值，选择秒、分钟、小时或天。例如节目单每 6 小时、频道列表每 1 天。范围为 60 秒至 30 天；从上次同类全量任务结束后计算（包括手动全量任务、失败或取消任务），部分频道/单来源任务不改变全量计划。
- 每天指定时间点：北京时间 24 小时制，例如 06:00,12:30,18:00。支持逗号、中文逗号、空格、换行分隔，自动去重、排序，每天最多 48 个时间点。
- 首次立即抓取：仅间隔模式首次建立调度记录时生效；每天定时按时间点执行。修改已有间隔后，从读取新设置时重新等待；重启本身不会重置已保存的正常计划。

频道列表自动抓取默认关闭，节目单保留旧开关、原间隔和首次启动设置。频道列表任务更新所有已注册来源的目录及 XMLTV 来源目录，不会自动新增管理频道，也不重排现有频道。来源失败保留原目录。

## 2.6.1：修复标准 XMLTV DTD 声明与错误提示

修复 2.6 错误拒绝标准 `<!DOCTYPE tv SYSTEM "xmltv.dtd">` 声明的问题。现在兼容文件头中不含内部子集的 XMLTV 外部 SYSTEM/PUBLIC 声明，解析前忽略声明，不下载或读取 DTD；内部子集、实体声明、重复及异常位置的声明继续拒绝。

失败原因会保留至来源页“最近错误”、任务详情和日志，区分下载 HTTP 状态、连接超时、文件解压、XML 格式错误（行列位置）、目录写入及单文件执行超时，避免统一提示掩盖原因。日志不输出来源 URL 中可能带有的访问参数。

2026-11-22 对用户提供的 `http://epg.51zmt.top:8000/e.xml.gz` 实测：HTTP 200，标准外部 DTD；修复后完整更新成功，100 个频道、6492 条节目，跳过 2 条不合规记录，耗时约 4.31 秒。此结果代表本地测试当时的网络和文件状态，NAS 网络仍以实际任务结果为准。

升级后在左侧“XMLTV 来源”勾选原来的来源，执行“更新选中 XMLTV 文件与频道目录”，或进入该来源保存以重新提交更新；无需删除原配置或改动地址。继续保留原 data 映射和端口。
## 2.6：搜索默认值、频道排序、XMLTV 文件来源

### 搜索与排序

- 完整频道编辑页、列表“编辑 / 补全”弹窗中的来源搜索框，默认填入当前 tvg-name，打开后可直接点击“查找”。修改 tvg-name 时，未自行改写的搜索词同步更新；手动输入的搜索词不会被覆盖。

- 表头仍支持临时升序、降序和组合排序；“上一个 / 下一个频道”跟随当前筛选和排序结果。此处自定义排序针对后台频道列表。

### 添加 XML / XML.GZ 地址

1. 左侧“XMLTV 来源 → 增加”，填写来源名称、可直接下载的 HTTP(S) XML/XML.GZ 文件地址，保持“启用自动更新”，保存。
2. 保存后自动提交文件更新任务；在任务中心查看结果。更新成功后，来源列表会显示频道数、节目数与最近成功更新时间。没有提交任务权限的账号，需要有权限的管理员执行更新。
3. 打开频道完整编辑页或列表“编辑 / 补全”，搜索 tvg-name，来源筛选选“XMLTV 文件”；结果中会标出具体文件来源的名称。
4. 点击“今日节目”预览，点击频道条目或“用此来源”选择，主来源设置为“XMLTV 文件”，核对后保存。来源 ID 自动生成，包含文件编号与编码后的外部频道 ID，请不要手动拼接。不同文件中同名 ID 不会混淆。
5. 首次选择后，在任务中心“抓取节目单”或频道列表动作中抓取所选频道。仅“更新 XMLTV 来源”会下载文件并同步目录，节目入库由“抓取节目单”执行。

可以添加多个文件地址；每个本地频道目前选择其中一个 XMLTV 文件频道，可同时保留原有网站来源作为其他备选。同一 XMLTV 映射改用另一文件频道时，会要求确认替换。

### 自动更新和持久化

- 任务中心开启自动抓取后，每一轮抓取节目单都会先更新所有已启用 XMLTV 地址，再从新快照读取所选频道，最后生成对外 XML/XML.GZ。无需改 Compose 参数。
- XMLTV 为主来源的启用频道每轮都会重新读取当前抓取天数的数据，即使原来已保存今天或明天节目，源文件修改仍能及时入库。自动更新间隔、任务整体超时、单文件超时沿用任务中心配置。
- 文件配置存在 data/epg.sqlite3，下载的解压 XML 与 SQLite 索引存在 data/xmltv 下；均通过原本 ./data:/data 持久化。
- 页面预览读取最近成功的本地文件快照，明确显示来源名称及文件更新时间。预览按钮只重新读取快照，不下载整份远端文件；刷新远端文件可用来源列表动作“更新选中 XMLTV 文件与频道目录”，或任务中心“更新 XMLTV 来源”。文件更新后会立即使旧预览缓存失效。
- 更新失败、返回 HTML、无有效频道节目、压缩损坏或解析超时，均保留原成功快照、目录和节目。任务结果与来源列表显示失败，预览旧快照也会提示最近更新失败；一个文件失败不阻断其他网站抓取。
- 禁用或删除文件配置后，目录条目停止供新选择；不会自动删除已存节目。旧频道映射需要改选其他可用来源。
- 为避免覆盖原来每个频道的选择，刷新文件目录不会自动创建、删除本地频道，也不会按同名静默切换现有映射。新增/替换频道仍由后台选择并保存。

支持 UTF-8 XMLTV、gzip（按文件头识别，地址可带查询参数）、数字时区偏移、跨午夜与缺少 stop 的节目。缺少时区时按上海时间处理；缺少 stop 时仅在有下一档时推算结束时间并标注。文件下载上限 100 MiB、展开上限 512 MiB、节目上限 200 万；兼容标准外部 XMLTV DTD 声明（不会读取 DTD）；拒绝内部子集、实体声明、UTF-16/32。仅重新生成对外 XML 不会下载远端文件。

## 2.4.2：简化 Compose 与任务设置

Compose 仅保留镜像、端口、本地目录、初始账号及容器运行配置；内置川流默认授权。需要反向代理时仍可按需补充 DJANGO_CSRF_TRUSTED_ORIGINS 等环境变量。

顶部与底部的保存区域增加“上一个频道 / 下一个频道”，并显示当前序号和频道总数。默认按频道ID排序；从筛选/搜索后的频道列表进入时，沿用列表的筛选条件与排序。

- 没有修改时直接切换，首尾对应按钮禁用，不循环回到另一端。
- 有未保存修改时提示“保存并切换 / 放弃修改并切换 / 取消”。保存验证失败会留在当前编辑页，便于修正。
- 保存时即使改变分组/名称使当前频道不再符合原筛选，也仍然前往原列表中的相邻频道。
- 本次仅新增网页导航，不改变频道ID或节目关联，没有数据库迁移。
